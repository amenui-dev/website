# 无障碍


画面由框架自己画，而不是用系统控件，所以运行时为辅助技术另外维护一份看不见的界面副本：无障碍镜像。每次重建时它和画面从同一棵树生成，两者不会对不上。

## 镜像

镜像里的每个元素有角色（和 WAI-ARIA 的同名角色对应：`Role::Button`、`Role::Slider`、`Role::Dialog`、`Role::Link` 等 30 多种）、名字（`El::label`）和状态：勾选、选中、数值和范围、层级、停用、展开、必填、无效、较长的 `description`，以及播报变化的区域用的 `live`（`Live::Polite` 或立即播报）。

| 平台 | 谁读镜像 |
|---|---|
| 原生（macOS、Windows、Linux） | AccessKit，挂在一个窗口节点下。元素的 id 来自它的键，所以重建以后读屏软件不会丢位置。 |
| 网页 | 一棵看不见的 DOM 树，带对应的 `role` 和 `aria-*` 属性。 |

焦点和激活双向同步：读屏软件移动焦点或按下按钮，会变成运行时自己的焦点变化和点击。

## 键盘

Tab 和 Shift+Tab 按树的顺序在可聚焦元素间移动。`El::tab_order(n)` 让元素排到前面（正数）或移出循环（负数）。`widgets::skip_link` 给页面加一个"跳到内容"链接，获得焦点时出现，并把焦点移进目标。`El::focus_shown` 让元素在获得键盘焦点前保持隐藏。

## 外观

窗口的深色或浅色设置，以及网页的 `prefers-contrast`，通过 `App::set_appearance` 交给应用；`prefers-reduced-motion` 同时交给运行时和应用，由它们缩短或去掉动效。

每个组件页写着它的键盘行为和角色。
